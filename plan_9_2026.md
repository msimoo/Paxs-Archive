## 1. Executive conclusion

PAXS is a substantial PACS/archive implementation, not an empty prototype. It contains DIMSE and DICOMweb services, SQLAlchemy persistence, background processing, reporting, multi-storage, tenant metadata, operational APIs, and multiple web interfaces. However, **feature presence must not be confused with production or diagnostic readiness**.

**Recommendation: block new public-facing, multi-institution, and diagnostic releases until the applicable critical findings below are fixed and independently tested.** Prioritize patient identity, archive integrity, authorization, and truthful UI behavior ahead of PostgreSQL, new AI models, or visual redesign.

The most important findings are:

1. A license-signing private key is embedded in a tracked PHP configuration file.
2. LDAP authentication contains a production-reachable test-credential fallback and shared local-password provisioning.
3. Several patient-data APIs lack mandatory authentication; `DICOMWEB_PUBLIC` is declared but not enforced.
4. Retrieval and destructive operations bypass tenant scoping; ingest identity handling also permits cross-institution collisions.
5. Storage path validation accepts `.` and `..`, with downstream uncontained writes and recursive deletion.
6. The newer report-save route can change finalized clinical content without mandatory authentication or the existing finalization workflow.
7. The served React study-detail drawer contains fabricated findings, demographics, and series counts.
8. Test fixtures can drop/recreate the database selected by an inherited `DATABASE_URL`.
9. Synthetic checks reproduced incorrect MPR voxel indexing and sagittal layout; quantitative measurements need validation.
10. Several visible actions only simulate success, while container dependencies, schema upgrades, and volume streaming contain additional defects.

**All issue statuses in this document are OPEN unless explicitly described as an existing mitigation.** This review does not claim that any issue has been remediated.

## 4. Critical bug register — fix before affected releases

### C01 — Tracked license-signing private key

**Priority:** P0 security containment. **Confidence:** confirmed embedded secret; deployed trust-chain usage requires owner confirmation.  
**Evidence:** `deploy/vendor-portal-php/config.php:35-72`, especially private-key block beginning at line 44; file is tracked by Git.

**Impact:** a key distributed in source must be treated as exposed. If trusted by deployed clients, it can undermine license issuance and revocation policy. The same config also contains static portal credentials/secrets.

**Fix plan:**
- Move signing into a restricted vendor-side service; clients receive public verification keys only.
- Rotate the embedded key and any active static portal secrets; design old-key retirement and license reissuance with the owner.
- Remove secrets from the working tree, add secret scanning, and coordinate a separate approved history-remediation procedure. Removing the current value alone does not remove historical copies.
- Do not silently rewrite Git history or invalidate installed customers' licenses.

**Acceptance:** no private signing material in source, images, installers, or published artifacts; scan current tree and history; old key rejected according to the approved transition policy; legitimate replacement licenses verified.

### C02 — LDAP fallback authenticates synthetic accounts

**Priority:** P0. **Confidence:** confirmed source defect.  
**Evidence:** `app/services/ldap_service.py:32-69,72-95`; `app/api/v1/ldap.py:29-56`; router included at `app/main.py:539`.

**Impact:** a hardcoded development credential pattern can produce an identity without a successful directory bind. New directory users also receive a shared known local password hash. The nominal LDAP bind path assigns a fixed role rather than validating real groups.

**Important nuance:** this service returns lowercase roles, whereas the destructive-role helper checks uppercase roles. Do not assume its token automatically passes that helper; authentication bypass, generic-auth endpoints, and inconsistent role behavior remain serious defects.

**Fix plan:** remove fallback credentials and shared local passwords; disable LDAP until explicitly configured; fail closed on bind errors; declare/validate LDAP configuration; use group-to-role mapping and one canonical role enum; disable local-password login for directory-managed accounts; add account-active checks, audit, and login-specific rate limits.

**Acceptance:** synthetic fallback credentials are rejected; directory outage does not authenticate; disabled users cannot log in; provisioned directory accounts cannot use a shared local password; role mapping and tenant assignment have positive/negative tests.

### C03 — Patient APIs are open and the privacy switch is ineffective

**Priority:** P0. **Confidence:** confirmed source defect.  
**Evidence:** `app/core/config.py:252-254`; `settings_service.py` registry; `app/main.py:295-303,507-555`; `dicomweb.py:327-347,359-422`; `dashboard.py:697-801`; `reports.py:160-177,227-228`; `volume.py:65-91`; `fhir.py` patient/imaging routes.

`DICOMWEB_PUBLIC` appears in configuration and the editable-setting registry, but the reviewed handlers do not enforce it. The viewer-page middleware does not protect `/dicom-web`, `/api/v1`, or `/fhir`.

**Impact:** callers can reach raw images, metadata, reports, and other patient information without the archive login. Optional user lookup is not an authorization requirement.

**Fix plan:** define explicit public and protected route groups; require authenticated identity on PHI routes by default; enforce private DICOMweb mode in shared dependencies; protect writes separately; design narrowly scoped expiring share-token access instead of opening the general API. Revisit PHI responses marked `public` cacheable, including `volume.py:139-148`.

**Acceptance:** route-matrix tests show anonymous private-archive access rejected; valid users still load the viewer; share links expose only their authorized study and expire/revoke correctly; shared/proxy caches cannot leak protected content.

### C04 — Tenant isolation fails on direct access and mutation

**Priority:** P0 for multi-tenant use. **Confidence:** confirmed source defect.  
**Evidence:** `query_service.py:157-192` defaults `include_all=True`; `dicomweb.py:390-406`; `dashboard.py:697-704,804-839`; `volume.py:65-91`; related export/share/report handlers.

**Impact:** list filtering is bypassed when a caller accesses a known UID directly. A role-authorized delete is not necessarily tenant-authorized. Authenticating these routes alone does not fix the isolation flaw.

**Fix plan:** introduce shared study/series/instance access guards; make tenant-scoped access the default and unrestricted access explicit; apply checks to retrieval, metadata, thumbnails, volume, export, share creation, reports, presigning, and delete. Enforce the same boundary before ingest overwrites or joins an existing UID.

**Acceptance:** a tenant-A user cannot read, change, delete, export, share, or overwrite tenant-B studies through any API; test both token and cookie authentication, absent tenant assignment, and the intentional admin exception.

### C05 — Storage paths can escape the root or target its parent

**Priority:** P0 data integrity. **Confidence:** sanitizer reproduced in isolation; live ingest exploit path not exercised.  
**Evidence:** `storage_service.py:44-67,179-180`; `storage/local.py:27-42,69-75`; writes at `dicomweb.py:873-886` and `app/dicom/receiver.py`.

The UID regex accepts `.` and `..` before the fallback rejects them. `_resolve` accepts absolute paths and uncontained relative paths. Recursive deletion uses the resulting path.

**Impact:** malformed identifiers can create objects outside the intended root; deletion of a malformed study could target the root or its parent. Actual ingest reachability depends on decoder/validation behavior, but the unsafe primitives are confirmed.

**Fix plan:** validate DICOM UIDs at ingest; reject dot segments, invalid syntax, and excess length; canonicalize paths and enforce root containment for reads/writes/moves/deletes; prohibit deleting the root itself. Move legacy absolute-path compatibility to an explicit validated migration path, not the general resolver. Consider junction/symlink escape cases on Windows.

**Acceptance:** pure tests reject `.`/`..`, path separators, absolute/drive paths, and escapes; sandbox-only integration tests reject malformed ingest; delete tests use disposable roots and never operate on a real archive. Preserve valid legacy data through a reviewed migration.

### C06 — Report-save bypasses finalized-report protection and delivery

**Priority:** P0 clinical integrity. **Confidence:** confirmed source defect.  
**Evidence:** `reports.py:173-224`; compare `report_service.py:109-117,282-312`.

**Impact:** `/reports/save` accepts optional authentication, takes the radiologist name from the request, directly updates clinical fields even for existing finalized reports, and sets final status without the normal finalization/ORU delivery path. This is a second, weaker reporting workflow alongside the original protected service.

**Fix plan:** consolidate create/edit/finalize into one authorized service contract; allow ordinary edits only in DRAFT; implement immutable finalized versions and explicit addenda; record the authenticated actor; use reliable, auditable ORU delivery with idempotency and retries; reject invalid status transitions and missing-study errors cleanly.

**Acceptance:** anonymous save rejected; finalized content cannot be silently overwritten; addenda preserve the original; signed/final status is not client-authoritative; finalizing through the UI follows the same service and observable delivery behavior as the API.

### C07 — Fabricated clinical content is shipped in the real study UI

**Priority:** P0 clinical UI. **Confidence:** confirmed source and referenced-bundle content.  
**Evidence:** `StudyDetailDrawer.tsx:40-42,128-145,160-167` under `study-list-ui/src/components/study-list/`; active bundle `app/static/studies-ui/assets/index-Bxwcl_Y6.js`.

**Impact:** any nonempty report status selects hardcoded normal findings/history/impression rather than the actual report body. Birth date, sex, and series counts are also invented. These are shown inside a real patient's study details.

A separate `PacsViewerDashboard.tsx` contains invented patient/AI findings and random HU values. Its viewer branch is imported, but `StudyListPage` does not invoke its `onOpenViewer` callback; treat this as bundled latent demo code, not evidence that all users currently see that screen.

**Fix plan:** remove fabricated content from production paths and bundles; fetch real report/demographic/series data; show explicit missing/loading/error states; remove the demo dashboard or isolate it in a separate nonproduction build with conspicuous labeling.

**Acceptance:** real studies with missing report bodies never show invented findings; demographic mismatches cannot occur; mock clinical strings/random measurements are absent from production assets; known report content matches exactly.

### C08 — Test fixtures can destroy a non-test database

**Priority:** P0 developer/operations safety. **Confidence:** confirmed source defect.  
**Evidence:** `tests/conftest.py:14-20,41-46,62-65,81-83`.

**Impact:** `setdefault` preserves an inherited `DATABASE_URL`, after which autouse fixtures drop/recreate tables and other fixtures delete all rows. The comments intentionally permit external database testing but there is no strong disposable-database safety gate.

**Fix plan:** default to a forcibly isolated database; require explicit test-only opt-in and an independently validated allowlist/name/sentinel for MySQL/PostgreSQL test databases; abort before imports/engine creation if isolation cannot be proven. Isolate storage backend, Redis, license files/heartbeats, backups, settings output, scripts, and subprocess/browser hooks too.

**Acceptance:** supplying a production-shaped URL causes an immediate refusal before any connection or DDL; default runs use only disposable data; negative tests prove the guard cannot be bypassed by inherited settings. Do not validate the guard by pointing it at production.

### C09 — MPR geometry and quantitative readouts disagree

**Priority:** P0 for diagnostic/quantitative use. **Confidence:** numerical/layout mismatch reproduced; full GPU/browser behavior not tested.  
**Evidence:** `app/static/viewer/paxs-mpr.js:1064-1099,1731-1738,1764-1772,1790-1822`.

- Coronal display uses X horizontally and Z vertically, but probe/ROI lookup swaps X and Z. Synthetic example: displayed voxel 22, probe voxel 36.
- Sagittal output ordering is Z-fast inside a Y loop, while the viewport dimensions expect Y-fast rows across Z. Probe/ROI and shader/crosshair conventions also need to be aligned.
- Cobb-angle calculation uses normalized viewport fractions rather than physical coordinates. With a 2:1 physical axis scale, a normalized 45-degree line can represent about 26.565 degrees. The ratio tool also needs spacing-aware validation.

**Fix plan:** centralize voxel-to-patient and viewport-to-voxel transforms; use one consistent axis convention; compute measurements in physical coordinates; test anisotropic spacing, orientation, flips, non-square matrices, and CPU/GPU agreement. Temporarily disable unvalidated quantitative tools in clinical builds.

**Acceptance:** asymmetric labeled phantoms identify the same voxel in every plane; HU/ROI results match reference calculations; ruler/angle/ratio tolerances are documented; orientation and patient identity overlays are verified by qualified reviewers.

### C10 — Patient IDs are globally conflated across institutions

**Priority:** P0 for multi-institution patient integrity. **Confidence:** confirmed schema/service behavior; no real records inspected.  
**Evidence:** `app/db/models.py:194-198`; `indexing_service.py:31-35,61-90,94-113,190-221,225-249`.

**Impact:** patients are looked up by globally unique `patient_id` without tenant or assigning authority. Different institutions using the same MRN join one patient row; later non-HIS demographics can overwrite earlier demographics. Missing IDs use one shared fallback identity. Existing study/SOP lookups also do not enforce the caller's tenant before joining/updating them.

**Fix plan:** define identity using tenant/assigning authority plus external patient identifier; preserve an internal surrogate ID; integrate the existing identity-management concepts into ingest; quarantine ambiguous/absent identifiers; reject unauthorized UID collisions before object writes. Plan a migration that reports conflicts for human reconciliation rather than auto-merging patient histories.

**Acceptance:** identical MRNs from two tenants remain distinct; a later ingest cannot rewrite another institution's demographics or image object; missing-ID studies do not silently merge unrelated people; controlled reconciliation preserves audit history.

## 8. Testing and release acceptance plan

### 8.1 Safe test harness requirements

Do not run the existing full suite against an inherited environment. Before enabling it:

1. Build a dedicated isolated environment using the selected supported Python version and a pinned dependency set.
2. Force a temporary SQLite database for default tests; allow external DB testing only for disposable allowlisted test databases with a sentinel and dedicated credentials.
3. Force local temporary storage; isolate Redis DB/instance and license paths; disable license online heartbeats and external webhooks.
4. Redirect backups, settings persistence, script directories, upload directories, and browser/subprocess hooks into test-owned locations or safe fakes.
5. Disable automatic workers/listeners; tests that require DIMSE/HL7 must bind loopback ephemeral ports explicitly.
6. Add a preflight test that aborts before application imports when any resource is not test-owned.
7. Only then collect/run pytest and record actual passes, failures, skips, duration, runtime, commit, and dependency versions.

### 8.2 Mandatory regression groups

| Group | Minimum coverage |
|---|---|
| Security | Anonymous/member/admin role matrix; LDAP negative paths; elevated self-registration; cookie expiry/revocation; trusted proxy behavior; XSS/upload rejection |
| Tenant/identity | Two institutions with identical MRNs; same/different UIDs; all read/write/export/share/report paths; missing identifiers; authorized reconciliation |
| Archive integrity | Malformed UIDs; path containment; duplicate/late instances; failed object write; failed DB commit; quota races; backend moves; safe retention/purge |
| Reporting | DRAFT edits only; finalization/addenda; authenticated signer; ORU success/failure/retry/idempotency; no fabricated content; selected-study consistency |
| Viewer | Asymmetric/anisotropic phantoms; per-plane HU/ROI; angle/ruler/ratio; orientation; mixed/multiframe series; odd-size downsample; CPU/GPU parity |
| Browser reliability | Real delete/forward/share requests; expired access token; navigation/filter changes; unknown health; canceled/failed decode; repeated MPR open/close |
| Schema/delivery | Empty install; upgrade from supported prior revision; schema parity; partial-upgrade refusal; backup/restore; clean Windows and container smoke tests |
| Scale/recovery | Multiple workers; process crash during ingest/routing/report delivery; object-store outage; retry deduplication; capacity/memory bounds; node failover |

### 8.3 Definition of done

An item can be marked complete only when:

- the source fix and every shipped build path are updated;
- a regression test fails before the fix and passes afterward where practical;
- authorization, patient identity, and data-integrity side effects are reviewed;
- relevant unit/integration/browser tests and migration checks pass in isolation;
- rollback or recovery is documented and demonstrated for data/schema changes;
- documentation states actual capability and limitations;
- clinical/quantitative changes have qualified reference validation, not just visual approval;
- an owner records evidence at the exact release commit.
