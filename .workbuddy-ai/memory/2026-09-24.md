### Backend (`app/api/v1/volume.py`) — the mirror image of Phase 2's guard

**client** mode. The two guards are symmetric and neither hard-blocks.

  `SERVER_SLICING_DISABLED = "Server-side slicing is disabled in client processing mode"`.
- New helpers: `_client_mode_active(user)` → `_resolve_mode(user) == "client"`;
  `_reject_server_slicing(endpoint)` → `HTTPException(503, detail=SERVER_SLICING_DISABLED,

  Phase 2's local `mode` var) for the `X-PAXS-Mode-Hint` header AND for the
  `server`-only `register_server_session(...)` call.
- `/mip` guard: same shape, `mip_mode`; success headers gained `X-PAXS-Mode-Hint: mip_mode`
  + `Access-Control-Expose-Headers`.
- **Ordering invariant (do not break):** ACL `require_series_access` runs BEFORE the mode
  guard. An unauthorised caller must get 403/404, never a `client` hint that would leak
  that the series exists.

### Viewer (`app/static/viewer/paxs-mpr.js`)
- `probeClientCapabilities()` per §6.2 — returns
  `{webgl, vram, workers, memory, total, maxTex, renderer}` (0–100). WebGL2 context +

  `navigator.hardwareConcurrency`; `navigator.deviceMemory`. Every browser API is wrapped

- `measureRTT(seriesUid)` per §6.3 — HEAD to `/info`, `cache:'no-store'`, AbortController,

### Two test-authoring traps worth remembering
1. **`/data?rescale=1` changes the dtype, not just the values.** Default = native
   uint16 (2 bytes/voxel); `?rescale=1` = float32 (4 bytes/voxel). So payload lengths
   legitimately differ 2x. Assert equal *geometry* (`X-Volume-Slices/Rows/Cols`),
   different `X-Volume-Dtype`, and the 2x `Content-Length` relation — never equal bytes.
2. **JS sandbox gotchas:** module-level `var` constants are NOT captured by
   `tests/js/extract.js::extractFunction` — inject `RTT_UNREACHABLE_MS`/`RTT_TIMEOUT_MS`
   into the sandbox scope. Fake WebGL contexts must expose `MAX_3D_TEXTURE_SIZE`
   (0x8073) / `UNMASKED_RENDERER_WEBGL` (0x9246) as own properties, or the probe scores 0.
   When a factory takes an options object, use `('gl' in opts) ? opts.gl : makeGl(opts)`
   so passing an explicit context is not clobbered.

# 2026-09-24 (later still) — Phase 4 hybrid dynamic engine (`plan_viewer_process.md` §3.3, §7, §8)

## Completed: Phase 4 — decision engine, split mode, fallback chain. All suites green.

### Backend — `app/api/v1/volume.py`
- **`resolve_hybrid_mode(webgl_score, rtt_ms, *, active_server_sessions=None,
  server_vol_cache_mb=None, gpu_vram_mb=0, hardware_concurrency=0) -> str`** implements the
  full §7.1 algorithm returning `client` | `split` | `server`. Six ordered branches:
  no-WebGL → server; saturating server (sessions ≥ max **or** cache ≥ budget) → client if
  score ≥ 20 else server; score ≥ threshold → client; RTT > threshold and score ≥ 20 →
  client; `20 ≤ score < threshold` → **split**; else server.
  - The two load kwargs default to `None` (not 0!) so an explicit `0` is honoured rather
    than falling through to live process state. This is the trap that would otherwise make
    tests pass while production misroutes.
  - `HYBRID_CLIENT_MIN_SCORE = 20` and `HYBRID_MODES = ("client","split","server")` module constants.
  - `_negotiate_hybrid(score, rtt)` kept as a thin pass-through wrapper for Phase 1 call sites.
- **Load reporting (§7.3)** — `server_load_headers()` → `X-PAXS-Server-Load: <active>/<max>`
  and `X-PAXS-Vol-Cache-MB: <mb>/<budget>`; `server_overloaded()`; `LOAD_HEADERS_EXPOSED`
  constant. Applied to `/negotiate`, `/info`, `/data` (both raw+npy branches), `/mpr/slice`,
  `/mip`, `/tiles`. Every `Access-Control-Expose-Headers` list had to be *extended* (not
  replaced) so the existing per-endpoint geometry headers stay readable.
- **`split` added to the mode vocabulary**: `_mode_endpoints("split")` exposes both `data`
  and `mpr_slice`; `_mode_capabilities("split")` → `{client_webgl_required: true,
  server_renders_slices: true, raw_volume_stream: true, gpu_mpr: false, gpu_mip: false,
  split_preview: true}`. All maps gained a `split_preview` key.
- **`/negotiate` hybrid branch** now reports `capabilities` for the *configured* mode
  (hybrid = union of both pipelines) while `effective_mode` is the per-request decision —
  a split session needs both pipelines advertised or the viewer picks one it cannot finish.
  Response also carries `hybrid_thresholds` (now with `min_client_score`) and
  `hybrid_decision: {webgl_score, rtt_ms, resolved}` so a mode choice is explainable.

### Gotchas worth remembering
- **`('gl' in opts)`-style defaults bite again, in Python**: `active_server_sessions=None`
  means "read live state", so an explicit `0` must be passed as `0`, not omitted. Do not
  change those defaults to `0` — it would silently disable the saturation branch in production.
- **`extractFunction` also misses `SPLIT_*`**: any new module-level `var` a Phase 4 function
  closes over must be injected into the sandbox (`SPLIT_DOWNSCALE`, `SPLIT_FINE_DEBOUNCE_MS`).

- `_mode_capabilities` for a hybrid deployment is the *union*, so asserting
  `client_webgl_required is True` on a hybrid negotiate is wrong; that flag is per-mode.
