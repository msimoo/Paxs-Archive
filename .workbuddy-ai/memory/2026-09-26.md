Full report: `PAXS_VIEWER_DIAGNOSTIC_AUDIT.md` (workspace root).
Method: static read of shipping artefacts + live curl probes against :8000.

## Applied (2 fixes, verified)
- **V2-1** `study-list-ui/vite.config.ts` — dev proxy targeted **8042** (Orthanc default)
  while the backend binds **8000** (`run_paxs.py`, `.env:4`, docker-compose.lb.yml:16).
  Fixed both targets to `:8000`; added a `/viewer` proxy entry so the template's
  `/viewer/paxs-study-list-enhance.js` resolves in dev. Verified: no 8042 target remains.

  never matched: OHIF's `generateAcceptHeader` **quotes** the value it emits
  (`transfer-syntax="*"`). Now normalises quotes/whitespace first. Low practical impact

## Key confirmed findings (NOT yet patched — documented with diffs)
- **V1-1 [HIGH]** `paxsFetch` (paxs-study-list-enhance.js:889) is a private helper with only
  3 call sites (576, 642, 937) and is **never** installed on `window.fetch`. Cornerstone's
  WADO-RS image requests therefore bypass refresh-and-retry → a single 401 is terminal →
  black viewport. Image requests auth by **session cookie**, not the 15-min bearer, so the
  trigger is any cookie/session invalidation, not token expiry.
- **V2-2 [HIGH]** `PUBLIC_BASE_URL` defaults to `http://0.0.0.0` (config.py:368) and `.env`
  never sets it → `sharing_service.share_url()` mints `http://0.0.0.0/viewer?share=…`.
  Every patient share link + QR code is dead. Also hits fhir.py:28, dashboard.py:166/890.
- **V2-3 [MED]** `getViewerUrl` (study-list-ui/src/lib/api.ts:39) uses `location.origin`,
  which drops a proxy path prefix. `PAXS_PUBLIC_BASE_URL` is only ever set by the **admin
  dashboard** (app.js:4353) — never in the study list → override always undefined.
- **V2-4 [MED]** No `root_path`/`X-Forwarded-Prefix`; uvicorn's `forwarded_allow_ips`
  defaults to 127.0.0.1 so a HAProxy container's X-Forwarded-* are ignored.
  `deploy/haproxy.cfg` never sets X-Forwarded-Host/Prefix.
- **V3-1 [HIGH]** `load_volume_array` (volume_service.py:1144) — lookup (1158) and insert
  (1198) are locked but the ~500 MB materialisation between them is not, with no in-flight
  registry → cold-cache stampede. Tile coalescing (line 845) dedups only identical tile
  keys, not the volume beneath them.
- **V3-2 [HIGH]** `paxs-mpr.js:1925` one synchronous `texImage3D` of a **Float32Array**
  (500 MB for 512×512×500) on the main thread. Guard at 1891 allows 256 M voxels (~1 GB).
  Worker allocates float32 even when rescale is identity (1579) — needless 2× memory.
- **V3-3 [MED]** negotiate gates first paint (paxs-mpr.js:1234); NEGOTIATE_TIMEOUT_MS=2500
  with RTT_TIMEOUT_MS=3000 inside it.
- **V3-4 [MED]** coarse preview uses `downsample=2` (1397), not the specified `4`
  (`SPLIT_DOWNSAMPLE=4` at 2401 is split-mode only).
- **V3-5 [LOW]** client `/data` fetches (1397, 1445) have no AbortController → a hung socket
  leaves `state.busy=true` forever.
- **V3-6 [LOW]** `_VOL_CACHE` evicts insertion-order not LRU; `_VOL_CACHE_MAX=8` <
  `HYBRID_MAX_SERVER_MPR_SESSIONS=20` → guaranteed thrash.

## Refuted hypothesis (worth remembering)
I first suspected **missing JPEG-LS/HTJ2K codecs** — `charlswasm_decode.wasm` etc. are absent
from disk and their URLs return the SPA shell (`200`, 6842 B, `text/html`), and
`DEFAULT_COMPRESSION="JPEG-LS"`. **Wrong.** Each codec module overrides `locateFile`
(`e.endsWith(".wasm") ? a.toString() : e`) with a webpack asset URL:
  - JPEG-LS (charls) → `776f756dd939124e.wasm`
  - JPEG2000 (openjpeg) → `0ddf166f7a343eda.wasm`
  - JPEG baseline/lossless (libjpeg-turbo) → `34b1e6b1deb5828e.wasm`
  - HTJ2K (openjph) → `37fa160cc3a47cfd.wasm`
All four exist and serve `application/wasm` (verified by curl). Codecs are FINE.

## V1-5 [MED] — the reason that mislead me (empirically proven)
`SpaStaticFiles.get_response` (app/main.py:608-620) falls back to `index.html` on **every**
404 under the mount. Proven live:
```
/viewer/does-not-exist.wasm  -> 200 text/html; charset=utf-8
/viewer/does-not-exist.js    -> 200 text/html; charset=utf-8
```
So a missing asset becomes a 200 with the wrong MIME, surfacing as a cryptic
`WebAssembly.instantiateStreaming failed` far from the real cause. Patch: 404 honestly for
asset extensions.

## Verified-correct (don't re-audit)
- Codec availability (above). `StudyInstanceUIDs` PascalCase end-to-end, no camelCase.
- `run_paxs.py` is env-driven; no hardcoded localhost:8000 in viewer JS or study-list src.
- `render_plane_tile` has correct L1 LRU + Redis L2 + single-flight tile coalescing.
- Worker pool transfers zero-copy with per-request timeouts + onerror settling (H15).
- Mode 503 guards don't misfire: `VIEWER_PROCESSING_MODE` defaults to `hybrid` and both

- WebGL context-loss handled → degrades to server Canvas 2D, not a silent black screen.

# Remediation Round 1 — all 5 high-impact fixes APPLIED & VERIFIED

Full record: `PAXS_VIEWER_REMEDIATION_ROUND1.md`. **248 assertions, 0 failures**
(JS 208: about 35 / toolbar 30 / icon 67 / cascade 5 / auth-guard 30 / tex-upload 41;
Python 40: spa-404 27 / volume-coalesce 13). All pre-existing suites still green.

## What changed
- **V1-1** `paxs-study-list-enhance.js` — new `paxsInstallFetchGuard()` +
  `paxsInstallXhrGuard()`, installed at boot before anything can fetch an image.
  Scoped to `PAXS_AUTH_RETRY_PATHS = ['/dicom-web/', '/api/v1/volume/', '/api/v1/reports/']`.
  Reuses the existing single-flight `paxsRefreshToken()`; one replay max; idempotent via
  `window.__paxsFetchGuard` / `__paxsXhrGuard`; exposed as `window.__paxsInstallAuthGuards`.
- **V1-5** `app/main.py` — `SpaStaticFiles` now falls back to index.html only when the path
  has no recognised asset extension (`_ASSET_EXTENSIONS`). Deliberately a DENYLIST, not
  "shell only if no extension": OHIF deep links embed UIDs in the path
  (`/viewer/studies/1.2.840.113619`) whose last segment looks like an extension.
  Also had to add `import os` to main.py (py_compile does NOT catch missing names).
  Live-verified: missing .wasm/.js/.css → 404; real codec wasm → 200 application/wasm.
- **V2-2** `app/core/config.py` — `PUBLIC_BASE_URL` default `""`; `field_validator`
  normalises (strips slash, downgrades unroutable 0.0.0.0/:: to ""); new
  `resolve_public_base_url(request)` resolves explicit → X-Forwarded-Host/Proto → Host →
  loopback `DEFAULT_PUBLIC_BASE_URL = "http://localhost:8000"`. Wired into
  `sharing_service.share_url(token, request=None)`, `share.py` (both endpoints now take
  `request: Request`), `dashboard.py` health + presign, `fhir.py` SERVER_BASE,
  `admin_panel_service.py` launch URL map. `is_routable_public_base_url()` helper.
- **V3-1** `app/services/volume_service.py` — `_IN_FLIGHT_VOLUMES: dict[str,
  threading.Event]` + `_IN_FLIGHT_VOLUMES_LOCK`, claim/wait loop in `load_volume_array`
  with `_IN_FLIGHT_WAIT_SECONDS = 180` / `_IN_FLIGHT_MAX_WAITS = 3`. Must be
  **threading.Event** (callers run via `asyncio.to_thread`).
- **V3-2** `app/static/viewer/paxs-mpr.js` — `uploadVolumeTexture(gl, tex, texBytes)`:
  ≤64 MB keeps the single `texImage3D`; >64 MB uses `texStorage3D` + `texSubImage3D` slabs
  (~8 MB/frame) across `requestAnimationFrame`. Abort guards: `GL_UPLOAD_GEN` (bumped by
  `releaseGl2()`) + `gl.isContextLost()`. Progress in `state.texUpload`.
- **Env/paths** `.env.example` (Redis section + PUBLIC_BASE_URL docs), `README.md`
  (new "Web interfaces (routes)" section documenting `/studies-ui` PLURAL).

## 🐞 Two bugs found in my own patches (caught by the tests I wrote)
1. **V3-1**: first version re-claimed ownership unconditionally on wake, so a failed owner
   made ALL waiters re-decode → 37 `_frame_array` calls instead of 13. Fixed with a
   bounded claim/wait loop (re-check cache after waking; only one claims next round).
2. **V3-2**: the chunk loop originally guarded on `state.gl2.volTex !== tex`, but `state.gl2`
   is assigned AFTER `uploadVolumeTexture()` returns — so the synchronous first chunk would
   have compared against the previous released gl2 and returned immediately, silently
   uploading NOTHING for every large volume. Fixed with the `GL_UPLOAD_GEN` counter.

## Correction to my own audit
I claimed the Redis L2 tier "silently no-ops". **Wrong.** Redis IS running on
127.0.0.1:6379, `REDIS_CACHE_ENABLED` defaults True, and `paxs:vol:*` keys are live.
Discovered when a V3-1 test returned a volume with ZERO decodes — a Redis hit. The test now
sets `REDIS_CACHE_ENABLED = False` in setup() and restores it in teardown(); the synthetic
volumes were flushed from Redis.

## Test-harness lessons (reusable)
- jsdom's real `XMLHttpRequest` hits the network and bypasses a mocked `window.fetch` — to
  test an XHR guard you MUST install a controllable fake XHR before `w.eval(SRC)`.
- `py_compile` does not resolve names; a missing `import os` compiles fine and only fails at
  runtime. Always follow compile with an import/boot smoke test.
- `{ ... }` is NOT a Python block — use `if True:` or a function.
- Redis/L2 caches make decode-count assertions non-deterministic; disable them in tests.
- Run test suites as separate Bash calls; `for` loops + `$()` command substitution +
  `>/dev/null` misbehave in this sandbox.

# Remediation Round 2 — V2-3 & V2-4 (reverse-proxy) + two zero-risk findings

Full record: `PAXS_VIEWER_REMEDIATION_ROUND2.md`. New guide: `deploy/REVERSE-PROXY.md`.
**421 assertions, 0 failures** (JS 229 + Python 192). tsc clean on study-list-ui.

## Key discovery (drove the whole design)
**Neither uvicorn 0.52 nor Starlette 1.3.1 reads `X-Forwarded-Prefix`** — uvicorn's
`ProxyHeadersMiddleware` handles only `X-Forwarded-Proto`/`-For`, and Starlette 1.3 has no
`proxy_headers` module at all. So a sub-path deployment had to be built from scratch.
Also: the viewer bundle derives its URLs from `window.PUBLIC_URL` + `config.routerBasename`
(so rewriting those in the shell is the correct lever), and **PAXS has no WebSocket
endpoints** (the task asked for ws support; I implemented it for correctness anyway).

## Applied
- **NEW `app/core/proxy_prefix.py`** — `ForwardedPrefixMiddleware` (pure ASGI, registered
  OUTSIDE the auth gate because a non-stripping proxy delivers `/paxs/viewer/...` which the
  gate's path check would miss — a fail-open for gating); `prefix_markup` (quote-anchored,
  idempotent, external URLs safe); `inject_boot` (sets `PAXS_BASE_PATH` + a fetch/XHR
  prefixing shim, injected right after `<head>` so it precedes all deferred bundles);
  `prefix_path`; `normalise_prefix` (rejects schemes and `..`).
- **`app/main.py`** — `_spa_shell()` / `_prefixed_text_asset()` for `/`, `/viewer`,
  `/studies-ui`, `/admin`, `/settings`, `/login`, fallback viewer, and a new explicit
  `/viewer/app-config.js` route (registered before the mount so it wins). With no prefix
  these delegate to `FileResponse` — **byte-identical**, asserted.
- **`app/core/config.py`** — `ROOT_PATH`, `FORWARDED_ALLOW_IPS`;
  `resolve_public_base_url()` appends the prefix without duplicating it.
- **`run_paxs.py`** — `proxy_headers`, `forwarded_allow_ips`, `root_path` + startup logs.
- **`study-list-ui/src/lib/api.ts`** — exported `appBasePath()`/`appBaseUrl()`;
  `API_BASE` + `getViewerUrl` use them. **`location.origin` was the V2-3 bug** (drops the
  prefix). `StudyListPage.tsx` auth fetches use `appBasePath()`. vite base UNCHANGED
  (rewritten at serve time → no rebuild needed).
- **`app/static/app.js`**, **`admin-bridge.js`**, **`viewer.js`** — prefix-aware links.
- **V3-5** `paxs-mpr.js` — `fetchWithDeadline` (120 s) on all 4 volume fetches.
- **V3-6** `volume_service.py` — `_VOL_CACHE` → LRU `OrderedDict` + `popitem(last=False)`.

## 🐞 Two bugs found in my own work (again by tests)
1. **Middleware**: forwarded `X-Forwarded-Proto` verbatim to any scope type, so an http
   request carrying `wss` got `scope["scheme"] = "wss"`. Fixed with cross-scope
   normalisation (`secure = proto in ("https","wss")`).
2. **`move_to_end` KeyError**: my first LRU patch called `move_to_end(cache_key)` after a
   hit that may have come via `alt_cache_key` — `KeyError` when that key is absent.
   Fixed by resolving *which* key hit first.

## 🐞 Third real gap found while verifying live
The auth gate built `RedirectResponse(f"/login?next=...")` — **root-absolute, dropping the
prefix**. Behind `/paxs/`, an anonymous visitor to `/paxs/studies-ui` bounced to `/login`
outside the app. Same for `/logout` and `role_landing()`'s `ROLE_LANDING` defaults. Fixed
with `prefix_path` at 6 sites (open-redirect guard on `?next=` preserved). Live-verified:
`/paxs/login?next=%2Fpaxs%2Fstudies-ui`.

## Test-harness lessons (reusable, repeats of earlier ones)
- **`{ }` is not a Python block** — I made this mistake TWICE more. Use `if True:` or a
  function. A one-liner that replaces column-0 `{`/`}` lines fixes it mechanically.
- TestClient sends `Host: testserver`, which IS routable — so
  `resolve_public_base_url(request)` legitimately returns `http://testserver`, not the
  loopback fallback. Don't assert the fallback for a request-scoped call.
- `NO_CACHE` in main.py is `"no-cache"`, not `"no-store"`.
- Recon regexes must allow a query string: `src="/viewer/app-config.js?v=37"` was missed by
  a `["'](/path)["']` pattern, which nearly hid the app-config rewrite.
- `/viewer` with NO query serves the **study-list** shell; only `?StudyInstanceUIDs=` serves
  the PaxsViewer bundle shell.
