# 2026-09-27 — Remediation Round 3 (memory budgets, observability, metrics auth)

**564 assertions, 0 failures** (JS 229 + Python 335). compileall + node --check clean.

## Applied

### Memory governance (V1-2 / V3-6)
- `app/core/config.py`: `DICOM_FRAME_CACHE_MB=256`, `VOLUME_CACHE_BUDGET_MB=1024`.
  Deliberately **independent** of `HYBRID_SERVER_VOL_BUDGET_MB` (policy/negotiation input)
  — these are hard memory caps, so a negotiation change can't raise worst-case RSS.
- `app/services/settings_service.py`: both registered under the `viewer` group with
  `min`/`max` (volume 64–65536, frame 16–16384). `_coerce()` gained optional per-key range
  enforcement; `config.py::_field()` now surfaces `min`/`max` so the UI can constrain input.
- Both caches moved from **entry counts to byte budgets**:
  `_VOL_CACHE` (volume_service) and `_FRAME_CACHE` (wado_rs_bulk_service).
  - Total recomputed from the dict, NOT a running delta — `_VOL_CACHE.clear()` is called
    directly by tests/resets and a stale counter would evict everything or nothing.
  - **Never evict the just-inserted entry** (`len > 1`): otherwise a volume larger than the
    whole budget is dropped immediately and the cache silently holds nothing.
  - **`0` = disabled**, returned as 0 — an `or` fallback would turn a deliberate disable
    into the full default budget (a real bug I introduced and caught).
  - `_FRAME_CACHE` **gained a lock**: the warm service decodes on a background thread
    (`warm_service.py:169`) while handlers decode on the event loop, and byte accounting is
    a read-modify-write.
- `validate_memory_budgets()` warns on `vol > hybrid` and negatives; logged at startup.

### V3-3 / V3-4 — deliberately NOT applied (per instruction)
Negotiate stays a gate; preview stays `downsample=2`. Reasoning recorded **at the call
site** in `paxs-mpr.js` so it isn't silently "optimised" back.

### Observability
- NEW `app/core/cache_stats.py` — dependency-free (no settings/numpy) so caches, `/metrics`
  and tests can all import it. One lock over ints. Counters cumulative (Prometheus
  semantics); gauges SET not incremented so they survive external clears.
- `/metrics` gains `paxs_cache_operations_total{cache,result}` (hit/miss/insert/evict),
  `paxs_cache_bytes`, `paxs_cache_entries`, `paxs_cache_budget_bytes`,
  `paxs_cache_utilisation_ratio`. Budgets read at **scrape time** so a settings override
  shows immediately. Both caches always emit (a vanishing series breaks rate()).
- NEW `app/core/dicom_diagnostics.py` — `decode_context()` / `transfer_syntax_label()`.
  Every decode failure now logs e.g.
  `transfer_syntax=1.2.840.10008.1.2.4.80 (JPEG-LS Lossless) | modality=CT bits=16/16
  samples=1 photometric=MONOCHROME2 512x512 frames=1 | series=… sop=… frame=3`.
  pydicom's `UID.name` is authoritative (used when available) with a fallback table.
  PHI-free (asserted: no PatientName/ID/BirthDate).
  Wired into 5 sites incl. `triage_service`'s previously **silent** skip (now DEBUG).
  Kept `log.exception` (traceback) rather than downgrading to `log.error`.

## 🐞 Two regressions/bugs found
1. **Round 2 broke `/api/v1/config`** — `dashboard.health()` gained a required
   `request: Request`, but `config.py` called `await health()`. → `TypeError`, HTTP 500.
   Fixed by extracting `health_payload(request: Request | None = None)` + thin `health`
   endpoint. **Lesson: `py_compile` and import smoke tests do NOT catch call-site signature
   drift — grep every caller when changing a signature.**
2. **Prometheus monitoring was entirely broken.** `/metrics` required
   `get_current_user_any` (401) while `deploy/prometheus.yml` scrapes with no credentials,
   and `MONITORING.md` claimed it was "unauthenticated by design". So every scrape 401'd,
   the whole `paxs-nodes` job was down, and `PaxsNodeDown` fired for every node.
   Fixed with `METRICS_ALLOW_IPS` (default loopback + RFC1918 = exactly what the compose
   network needs): listed peers scrape unauthenticated, everyone else authenticates.
   Reuses `TrustedHosts` (renamed from `_TrustedHosts` in `proxy_prefix.py`, now public).
   Deliberately NOT a blanket "make it public" — the payload discloses version/topology/load.

## Also
- `validate_memory_budgets` first version warned that 1024 MB can't hold 20 × 500 MB
  volumes — i.e. it fired on the **shipped defaults**. Removed the volume-size heuristic:
  the byte budget is the authoritative constraint and the session cap is an admission
  limit; a warning that's wrong by default trains people to ignore it. Real pressure is
  now *measured* via `paxs_cache_utilisation_ratio`. Documented in the docstring.
- `deploy/MONITORING.md`: cache panels + two new alerts (`PaxsDecodeCacheThrashing`,
  `PaxsDecodeCacheEvicting`) + corrected the `/metrics` auth claim.

## Test-harness lessons
- `cache_stats` counters are process-lifetime → tests MUST `cache_stats.reset()` in setup,
  or every test sees prior totals (caught as "inserts counted -> 9, expected 4").
- In a FastAPI test route, an **unannotated** `request` param becomes a *query* param →
  422. Annotate `request: Request`. (Dependencies resolve first, which is why a public-IP
  case returned 401 while a trusted-IP case returned 422 — a confusing asymmetry.)
- pydicom's `UID.name` is authoritative and may differ from the common initialism
  (HTJ2K → "High-Throughput JPEG 2000 Image Compression (Lossless Only)").
- To test a decode *fallback* succeeding, build a valid encapsulated frame with
  `pydicom.encaps.encapsulate([bytes])` — `generate_frames` just splits item tags.
- Reminder: `{ }` is not a Python block (made this mistake again; a column-0 brace
  replacement one-liner fixes it mechanically).
