# 2026-10-08 — Lossy compression engine remediation (C-2 / C-3 / C-4)

## What was done

Rewrote `app/services/lossy_compression_service.py` so lossy re-compression is
safe, and added a fail-closed guard.

### Changes
- **`app/core/config.py`**: new `LOSSY_COMPRESSION_ENABLED: bool = False` (fail-closed).
- **`lossy_compression_service.py`** (rewritten):
  - `dataset_to_image` removed from the pipeline — compression now runs on the
    native `ds.pixel_array` via `Dataset.compress()` (pyjpegls / openjpeg).
  - `LOSSY_TARGETS` = {`.81` JPEG-LS Near-Lossless, `.91` JPEG 2000 Lossy} only.
    **JPEG Baseline (`.50`) has NO pydicom encoder** → rejected (this is why the
    old code hand-rolled a baseline JPEG and mislabelled it).
  - `validate_target_transfer_syntax()` — encoder must exist for the target.
  - `_assert_geometry_preserved()` — BitsAllocated/BitsStored/PhotometricInterpretation/
    SamplesPerPixel/Rows/Columns must be identical after encoding.
  - Decodes the transcoded codestream once before staging (proves readability).
  - `is_eligible_source()` — uncompressed or verified-lossless only; all lossy
    UIDs excluded (query-level `notin_` + per-instance re-check).
  - Writes via `storage_service.stage_dataset_with_quota` → `StagedObject.promote()`.
  - Both entry points no-op when `LOSSY_COMPRESSION_ENABLED` is false.
- **`app/db/models.py`**: `LossyCompressionRule.transfer_syntax_uid` default
  `.50` → `.81` (`.50` can never be encoded).
- **`app/api/v1/lossy_compression.py`**: default target `.81`; create/update reject
  unsupported targets with 400; `/run` reports `disabled`/`skipped_instances`.
- **`.env.example`**: documents `LOSSY_COMPRESSION_ENABLED=false`.

## CRITICAL gotcha discovered (worth remembering)

`pydicom.Dataset.compress()` defaults to **`generate_instance_uid=True`** — it
mints a NEW SOPInstanceUID, so the transcoded object lands at a *different*
storage key and the DB row still points at the old file. For in-place
re-compression you MUST pass `generate_instance_uid=False`, and assert the
SOPInstanceUID is unchanged. This cost a debugging cycle: the DB showed `.81`
while the file on disk was untouched.

# 2026-10-08 (cont.) — Viewer memory / WebGL fixes (H-10, H-11, H-12, L-8)

## H-11 — the patch existed in TWO places
`HTMLCanvasElement.prototype.getContext` was overridden in **`viewer/index.html`**
(inline `<script>` in `<head>`) *and* in `paxs-study-list-enhance.js`. The
index.html one ran first and set `__paxsVtkGuardInstalled`, so the JS copy was a
no-op — **index.html was the one actually in effect**. Both removed.
The only canvas read back via `drawImage` is the MPR GPU renderer
(`paxs-mpr.js` `drawGl2` → `vp.ctx.drawImage(g.renderCv, ...)`), so that one
`getContext` call now requests `preserveDrawingBuffer: true` locally.

  window `SERVER_FRAME_KEEP_RADIUS = 10`, detaches + `URL.revokeObjectURL`s

  `THUMB_CACHE_MAX = 64` (`_cacheThumb`/`_releaseThumb`/`releaseAllThumbs`) plus a
