- **EDIT** `app/static/viewer/paxs-mpr.js` — added read-only telemetry bridge

  capabilities/serverLoad/fallbackMode) or `null` when no volume session is active.
- **EDIT** `app/static/viewer/index.html` — registered `<script defer src="/viewer/paxs-about.js?v=37">`
  immediately after paxs-mpr.js.

## Design decisions (important for future edits)
- Interception: `document.addEventListener('click', fn, true)` matching
  `[role="menuitem"], [data-cy*="about"]` + label test (about/حول/…). preventDefault +
  stopPropagation + stopImmediatePropagation → stock OHIF modal never renders.
- **Traps are BUBBLE phase on the overlay, NOT capture.** Capture at the overlay would
  swallow the close button's own click handler. Bubble still beats document-level OHIF
  handlers (overlay is deeper) and keeps events off the viewports.
- Overlay is `position:fixed; inset:0; z-index:2147483000` → viewport canvases can never
  be the event target, so no tool bleed-through.
- Synthetic `pointerdown` on `document.body` after open, to dismiss the Radix dropdown
  that never got its own click (we swallowed it).
- Entrance/exit: opacity + scale(.96→1), 150ms; `.paxs-about-open` added on a double-rAF
  guarded by `activeOverlay === overlay` (prevents an open/close race).
- Light theme supported via `:root[data-theme="light"]` overrides.
- Public API: `window.paxsOpenAbout()` / `window.paxsCloseAbout()`.

# 2026-09-25 (later) — Header toolbar modernization (Phase 0 + Phase 1)

## Phase 0 findings (two DEAD selectors found in the existing theme)
1. **Active-tool state never applied.** Tool buttons are Radix `Toggle` /
   `ToggleGroupItem`. Verified in the bundle (byte ~2 299 291 / ~2 302 427):
   the pressed state is `data-state="on"` + `aria-checked="true"` (type="single"
   → `role="radio"`) or `aria-pressed="true"` (bare Toggle). The theme targeted
   `[data-state="active"]` — which Radix never emits → **active glow was dead**.
2. **Toolbar wrapper selector never matched.** Theme used
   `div[class*="relative flex justify-center"]`; that string appears **0 times**
   in the current bundle (it is an older-fork class).
3. `.paxs-tool-default` was referenced by `paxs-study-list-enhance.js` but never
   defined in CSS → default tools had no styling.
4. `applyToolColor()` wrote inline SVG `width/height/padding/color` on a 2s
   interval → inline styles beat class rules, so any CSS-based icon sizing was
   being overridden every 2 seconds.

## Files changed
- **NEW** `app/static/viewer/paxs-toolbar-enhance.js` — derives the toolbar
  container at runtime (lowest common ancestor of `header button[aria-label]`)
  and tags it `.paxs-toolbar`; tags `.paxs-tool` + category class +
  `.paxs-tool-active` + `.paxs-icon`; injects the telemetry pill; tags patient
  info / modality badges. MutationObserver + 1.5s interval. Exposes
  `window.__paxsToolbarEnhance`. Never touches listeners/commands/tool groups.
- **EDIT** `app/static/viewer/paxs-viewer-theme.css` — new section 9 (header
  glassmorphism, brand badge, toolbar capsule, 6px tool buttons, ACTIVE state
  fixed, category tints, 1.75px stroke refinement, dropdown menus, telemetry
  pill, modality badge).
- **EDIT** `app/static/viewer/paxs-study-list-enhance.js` — `applyToolColor()`
  no longer writes inline SVG styles (CSS is now authoritative); still adds the
  category class.
- **EDIT** `app/static/viewer/index.html` — registered
  `<script defer src="/viewer/paxs-toolbar-enhance.js?v=37">` after paxs-about.js.

# 2026-09-25 (later) — Modern medical icon injection (replacing stock OHIF glyphs)

## Premise check (honest finding)
The task stated OHIF's tool SVGs are filled silhouettes. In THIS build that is
**partly true**: the bundle ships **Lucide** stroked icons (Ruler, ZoomIn, Hand,
Sun, Grid2x2, RotateCw, Crosshair, Contrast, Cuboid, LayoutGrid, Spline, Activity
all present as definitions) but also contains 129 `fill:"currentColor"` glyphs.
Either way, an explicit injection map is the only way to guarantee the
1.75px medical line-art aesthetic — so it was implemented as directed.

## Implementation (`app/static/viewer/paxs-toolbar-enhance.js`)
- **`ICONS`** — 27 hand-authored 24x24 line-art glyphs: wl, zoom, pan, scroll,
  cine, length, bidi, angle, cobb, probe, mpr, layout, invert, rotate, flip,
  ellipse, rectangle, freehand, eraser, annotate, text, capture, undo, redo,
  segmentation, report, more. All pure strokes (no fills).
- **`ICON_RULES` + `RULE_RE`** — ordered, **word-boundary** regex matcher
  (`\b…s?\b`), compiled once. `injectIcon()` re-attributes the EXISTING `<svg>`
  node (viewBox/fill/stroke/stroke-width/linecap/linejoin) and swaps its
  innerHTML, then stamps `data-paxs-icon="modernized"` for idempotency.
  The `<svg>` ELEMENT is never replaced → listeners, `data-state`,
  `aria-checked` all survive.
- **`isChevron()`** — a dropdown caret svg inside the same button is skipped, so
  only the real tool glyph is swapped.
- CSS (section 9.7): `.paxs-toolbar button svg, .paxs-tool svg { fill:none !important;
  stroke: currentColor !important; }` plus the 1.75px stroke refinement.

## 🐞 Two real bugs the test caught (substring matching)
- `"Rectangle"` contains **"angle"** → was getting the Angle glyph.
- `"Freehand"` contains **"hand"** → was getting the Pan glyph.
Fixed by switching from `indexOf` to word-boundary regex. Also moved
`rectangle` ahead of `angle` and dropped the over-broad `label` keyword.

## Verification
- `node --check` clean; served on :8000 → toolbar-enhance.js 200 (24 534 B),
  theme CSS 200 (39 774 B).
- **48/48** new icon assertions PASS (`.workbuddy-ai/tmp/icon-test.js`):
  attribute normalisation, filled-glyph removal, per-tool glyph correctness for
  27 labels, attribute/listener preservation across re-enhancement, unknown

  de/re-activation.
- **30/30** prior toolbar assertions still PASS (no regression).

  `.workbuddy-ai/tmp/toolbar-preview.html`.

# TASK E — Precision 1.75px Medical Vectors (final re-spec)

User issued an exact final spec for the icon-injection map: a `PAXS_ICONS`
dictionary keyed by icon id, `data-paxs-icon="<icon_id>"` stamping, a debounced
observer (~100ms), `.paxs-modern-svg` CSS, and `?v=38` cache busting.

## Key renames vs Task D (breaking — old keys removed)
`wl→windowLevel`, `freehand→roi`, `eraser→clear`, `annotate→arrow`.
`reset`/`rotate` swapped order in `ICON_RULES` so "Reset" can't be eaten by
`rotate`'s `reload` keyword; `rectangle` stays ahead of `angle`.

## What changed
- **`app/static/viewer/paxs-toolbar-enhance.js`** — rewritten. New `PAXS_ICONS`
  (exact user path data), `resolveLabel()` now reads
  `aria-label → data-cy → title`, `ICON_FLAG='data-paxs-icon'` /
  `ICON_CLASS='paxs-modern-svg'`, debounced MutationObserver
  (`OBSERVER_DEBOUNCE_MS=100`, coalesced via a single `pending` timer), and the
  1.5s safety-net interval retained for attribute-only `data-state` flips.
- **`app/static/viewer/paxs-viewer-theme.css`** — section 9.7b added
  (`.paxs-modern-svg` 19px / 1.75px / `fill:none` / `stroke:currentColor`;
  hover `scale(1.08)` + `#38bdf8` scoped `:not(.paxs-tool-active)`; active
  `box-shadow: 0 0 12px rgba(6,182,212,.3)` + white stroke).
- **`app/static/viewer/index.html`** — cache busters bumped
  `paxs-toolbar-enhance.js?v=38` and `paxs-viewer-theme.css?v=38`.

## 🐞 Real cascade bug found & fixed
`.paxs-tool svg` has specificity **(0,1,1)** and would beat a bare
`.paxs-modern-svg` **(0,1,0)** on `width`, silently pinning the icons back to
**18px** instead of the specified **19px**. Fixed by extending the selector to
`.paxs-modern-svg, .paxs-tool .paxs-modern-svg, .paxs-toolbar button .paxs-modern-svg`
(0,2,1). Verified with a new `cascade-test.js` that asserts the *resolved*
`getComputedStyle` width is `19px`, not `18px`.

Note: `fill="none"` on the ROOT svg does **not** kill the intentional solid
anchor dots (length/angle/probe/invert) — a presentation attribute on an inner
element beats inherited value. No `.paxs-icon *` rule sets `fill`, so the dots
survive. Deliberate, documented in both the JS header and the CSS comment.
