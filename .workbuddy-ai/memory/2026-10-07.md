## Verified critical defects (grounded, not speculative)

- **C-1** `split_merge_service.py` — `_rewrite_instance_study_uid` writes the rewritten
  dataset to the new key, then the caller overwrites that key with the ORIGINAL bytes →
  stored DICOM header keeps the old StudyInstanceUID/PatientID while the DB moves on.
- **C-2/C-3/C-4** `lossy_compression_service.py` — "lossy compression" routes pixels through
  `imaging.dataset_to_image` (display pipeline: VOI windowing + 8-bit RGB) → irreversible
  diagnostic-data destruction; JPEG-LS target emits a baseline-JPEG codestream; already-lossy
  data is re-encoded (only baseline UID excluded).
- **C-5** `fhir.py` — `search_patient` / `read_patient` are NOT tenant-scoped (unlike
  `search_imagingstudy`) → cross-tenant PHI disclosure via `/fhir/Patient`.
- **H-1** `prefetch_service.py` calls `sender.c_move_study`, which does not exist (only
  `send_move`) → prior prefetch silently dead.
- **H-2** `routing_service.dispatch_study_to_node_sync` leaks a temp `.dcm` per S3 instance
  (`delete=False`, never unlinked).
- **H-3/H-4** `hl7.py` — thread-per-connection + unbounded MLLP buffer (DoS).
- **H-5** `dicomweb_client.wado_retrieve` checks the size cap AFTER buffering `resp.content`.
- **H-6/H-7** `lifecycle_service` — partial tiering leaves a study split with a lying state
  flag; purge deletes metadata even when object deletion fails (orphaned PHI).
- **H-8/H-9** `sender.py` — one association per instance, no ACSE/DIMSE timeouts; C-GET
  returns Success even when local ingest failed.
- **H-10/H-11/H-12** viewer JS — unbounded `serverFrames` Image/objectURL cache during scroll;
  global `getContext` patch forcing `preserveDrawingBuffer` on every WebGL context; thumbnail
  object URLs never revoked.
- **H-13** blocking DIMSE/DB I/O in `async def` (`nodes.ping_node`, `config.py`,
  `split_merge_service`, `scripts.py`).

## Architecture facts worth remembering

- Async engine uses **NullPool**; sync engine (receiver + worker) uses a bounded QueuePool
  (`DB_POOL_SIZE=5`, `MAX_OVERFLOW=10`) — shared, so a C-STORE burst can exhaust it.
- `receiver.handle_store` runs `asyncio.run(_index_async(...))` **per instance**.
- `_BUNDLE_CACHE` in `volume_service` is keyed by `series_uid` only — NOT tenant-scoped
  (latent cross-tenant read; call sites currently ACL first).
- Three L1 caches: frame (byte budget), volume (byte budget), tile (**count-bounded 256**).
- `.env.example` ships `DEFAULT_COMPRESSION=RLE` / `TOKEN_EXPIRE_MINUTES=480` vs code
  defaults `JPEG-LS` / `15`.
- No ATNA (RFC 3881) audit messages — only a private `audit_log` table.

## C-1 fix (split/merge header overwrite) — implemented & tested

`app/services/split_merge_service.py` rewritten:
- `_rewrite_instance_study_uid` now **returns the rewritten bytes** (`ds.save_as(BytesIO,
  enforce_file_format=True)`); the blind `except` is gone — errors propagate.
- New `_rewrite_and_relocate(session, targets, ...)` helper enforces all-or-nothing:
  write new object → **verify by read-back** (`_verify_rewritten_instance`) → flush DB →
  only then unlink the superseded source. On failure it deletes the objects it wrote and
  re-raises (caller's transaction rolls back); source objects are never touched.
- Both callers save the generated bytes to `new_key` and never re-read `old_bytes`.
- Removed unused `pydicom` / `Patient` imports.

Test: `tests/test_split_merge_integrity.py` (4 tests, all pass). Autouse fixture points
`SCRIPTS_DIR` at an empty temp dir so ingest doesn't fire the real `scripts/` hooks.

## NEW finding discovered while testing C-1 (H-16, High)

`indexing_service.resolve_patient_identity` wraps the patient INSERT in
`session.begin_nested()` (SAVEPOINT). On **SQLite/aiosqlite a released SAVEPOINT is NOT
undone by an outer rollback** — reproduced in isolation:
`PLAIN ROLLBACK persisted: False` vs `NESTED ROLLBACK persisted: True`.
So any failed ingest after patient resolution leaves an **orphan `patients` row**.
Fix = SQLAlchemy's pysqlite recipe (`isolation_level=None` + explicit `BEGIN` on the
SQLite engines in `app/db/session.py`). Not yet applied (out of C-1 scope, needs
full-suite validation). Recorded in `audit_and_roadmap/02_CRITICAL_BUGS_AND_ISSUES.md`.
Consequence for tests: the C-1 rollback test omits `target_patient_id` to avoid the
savepoint path; documented inline.
