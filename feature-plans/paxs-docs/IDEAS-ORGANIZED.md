## 🔴 الفئة A — النواة الأساسية (Core MVP)

*هذه الأفكار هي الحد الأدنى لتشغيل نظام PACS حقيقي.*

### A1. استقبال صور الأشعة عبر DICOM DIMSE
- **الفكرة:** خادم يستمع على المنفذ 10400 لاستقبال صور الأشعة من أجهزة CT/MRI
- **البروتوكول:** C-STORE SCP عبر مكتبة `pynetdicom`
- **الأنواع المدعومة:** C-STORE, C-FIND, C-GET, C-MOVE
- **الأولوية:** 🔴 ضروري في Phase 2

### A2. فهرسة البيانات الطبية في MySQL
- **الفكرة:** استخراج DICOM Tags وحفظها في قاعدة بيانات هرمية 4 مستويات
- **الهيكل:** Patient → Study → Series → Instance
- **التقنية:** SQLAlchemy 2.0 Async + Alembic
- **الأولوية:** 🔴 ضروري في Phase 1

### A3. التخزين المنظم للملفات على القرص
- **الفكرة:** حفظ ملفات .dcm بمسار منظم حسب الـ UIDs
- **المسار:** `storage/{StudyUID}/{SeriesUID}/{SOPUID}.dcm`
- **الأولوية:** 🔴 ضروري في Phase 1

### A4. واجهات DICOMweb القياسية (QIDO-RS, WADO-RS, STOW-RS)
- **الفكرة:** REST API متوافق مع معايير DICOM PS3.18
- **التقنية:** FastAPI
- **الاستخدام:** يُغذّي عارضات الصور مثل OHIF
- **الأولوية:** 🔴 ضروري في Phase 3

### A5. تكامل OHIF Viewer v3
- **الفكرة:** عارض صور طبي في المتصفح مباشرة بدون تثبيت
- **الاتصال:** DICOMweb API عبر Nginx
- **الأولوية:** 🔴 ضروري في Phase 3

## 🟡 الفئة B — ميزات تقنية (Technical Enhancements)

*تحسينات جوهرية للأداء والموثوقية.*

### B1. ضغط الصور الطبية Lossless في الخلفية
- **الفكرة:** ضغط الصور بعد الاستقبال بدون أي فقدان للجودة
- **الخوارزميات المدعومة:**
  - JPEG-LS Lossless (UID: 1.2.840.10008.1.2.4.80) — أفضل للـ CT/MRI
  - JPEG 2000 Lossless (UID: 1.2.840.10008.1.2.4.90) — أفضل للـ CR/DX
  - HTJ2K Lossless (UID: 1.2.840.10008.1.2.4.201) — أسرع × 10 للمتصفح
  - RLE (UID: 1.2.840.10008.1.2.5) — للـ Ultrasound
- **نسبة الضغط:** 50-70% توفير في المساحة مع 100% جودة
- **التنفيذ:** Celery Worker + Redis Queue (لا يعطل الاستقبال)
- **التقنية:** `imagecodecs`, `openjph`, `pydicom.compress()`
- **الأولوية:** 🟡 Phase 2-3

### B2. نقطة الدخول الموحدة للـ Windows EXE
- **الفكرة:** دمج DICOM Receiver + FastAPI في ملف تنفيذي واحد
- **آلية العمل:** Threading — كل خدمة في thread منفصل
- **الأدوات:** `run_paxs.py` + PyInstaller `--onedir`
- **الإضافات:** imagecodecs, pydicom, pynetdicom, openjph
- **نتيجة:** ملف EXE يعمل على Windows بدون Python
- **الأولوية:** 🟡 Phase 5

### B3. تثبيت كـ Windows Service
- **الفكرة:** تشغيل PAXS تلقائياً مع إقلاع الويندوز بدون تسجيل دخول
- **الأداة:** NSSM (Non-Sucking Service Manager)
- **الفائدة:** خادم دائم التشغيل في بيئات المستشفيات
- **الأولوية:** 🟡 Phase 5

### B4. معمارية التخزين الهرمي الذكي (Smart Tiered Storage)
- **الفكرة:** توزيع الصور على 3 مستويات حسب العمر
- **المستويات:**
  - Hot (NVMe): < 30 يوم — أسرع وصول
  - Warm (MinIO/NAS): 1 شهر – 1 سنة — مضغوط Lossless
  - Cold (S3/Glacier): > 1 سنة — أرخص تكلفة
- **الأولوية:** 🟡 Phase 4

### B5. JWT Authentication + RBAC
- **الفكرة:** نظام صلاحيات متعدد الأدوار
- **الأدوار:** RADIOLOGIST, PHYSICIAN, ADMIN, PATIENT
- **التقنية:** `python-jose`, `passlib[bcrypt]`
- **الأولوية:** 🔴 Phase 4

## 🟢 الفئة C — ميزات تجارية (Business Value)

*أفكار تميز PAXS عن الأنظمة التقليدية وتضيف قيمة تجارية.*

### C1. نظام مشاركة المريض الذكي (Zero-CD)
- **الفكرة:** QR Code ورابط مؤقت للمريض بدلاً من CD/DVD
- **التفاصيل:**
  - رابط صالح 30 يوماً بـ `secrets.token_urlsafe(32)`
  - حماية بـ OTP عبر رقم هاتف المريض
  - يفتح PWA في أي متصفح بدون تثبيت
  - يُرسل تلقائياً عبر SMS أو WhatsApp
- **التقنية:** `qrcode`, `secrets`, MySQL (جدول patient_shares)
- **الأولوية:** 🟡 Phase 3

### C2. التوجيه الذكي الآلي (Smart DICOM Router)
- **الفكرة:** توزيع الفحوصات على أجهزة مختلفة حسب قواعد مخصصة
- **أمثلة:**
  - CT طوارئ → يرسله فوراً لجهاز الاستشاري المناوب
  - فحص > 1 GB → يوجهه للتخزين السريع مباشرة
  - Mammography → يرسله لوحدة أشعة الثدي
- **التقنية:** Rules Engine + C-STORE SCU
- **الأولوية:** 🟢 ميزة مستقبلية

### C3. بوابة HL7 / FHIR (HIS Integration)
- **الفكرة:** ربط PAXS بنظام إدارة المستشفى EMR/HIS
- **المنفعة:** عند فتح فحص في OHIF، يظهر السجل الطبي الكامل جانباً
- **البيانات:** التحاليل السابقة، الأدوية، العمليات
- **الأولوية:** 🟢 ميزة مستقبلية

### C4. محرك إخفاء هوية المريض (Anonymizer)
- **الفكرة:** تحويل الفحوصات لبيانات جاهزة للبحث العلمي أو تدريب AI
- **العملية:**
  - حذف: الاسم, رقم الملف, اسم المستشفى, تاريخ الميلاد
  - الإبقاء على: العمر, الجنس, الملاحظات الطبية
- **الامتثال:** HIPAA / GDPR
- **الأولوية:** 🟢 ميزة مستقبلية

### C5. دعم بيئات ضعيفة الاتصال (Edge PACS)
- **الفكرة:** نود محلي خفيف يعمل Offline-First
- **آلية العمل:**
  - استقبال وتخزين الصور محلياً فوراً
  - رفع السحابة (Background Queue) عند توفر الاتصال
  - مزامنة ذكية بضغط الصور لتوفير bandwidth
- **الاستهداف:** مراكز صحية نائية / شبكات ضعيفة
- **الأولوية:** 🟢 ميزة مستقبلية

## 🔵 الفئة D — ميزات مستقبلية بالذكاء الاصطناعي (AI-Powered)

*أفكار تجعل PAXS منصة من الجيل التالي.*

### D1. نظام فرز الطوارئ بالذكاء الاصطناعي (AI Emergency Triage)
- **الفكرة:** اكتشاف الحالات الحرجة تلقائياً عند استلام الفحص
- **الحالات المكتشفة:**
  - نزيف المخ (Stroke)
  - انكماش الرئة (Pneumothorax)
  - الكسور الحادة
- **آلية العمل:**
  - عند استقبال فحص → إرساله لنموذج AI في الخلفية
  - اكتشاف حالة حرجة → رفع الفحص لأعلى Worklist
  - إرسال إشعار فوري (Push Notification / Telegram Bot)
- **التقنية:** MONAI + TorchServe + Celery
- **الأولوية:** ⭐⭐⭐ عالي التأثير

### D2. العرض التشاوري الفوري (Real-Time Collaborative Viewer)
- **الفكرة:** "Figma للراديولوجيا" — أطباء متعددون على نفس الفحص في الوقت الحقيقي
- **المميزات:**
  - رابط فريد لكل جلسة تشاورية
  - مزامنة Zoom, Rotation, Window/Level, قياسات
  - مؤشر ماوس حي يوضح أين ينظر كل طبيب
  - دردشة نصية أو صوتية داخل العارض
- **التقنية:** WebSockets + FastAPI WS
- **الأولوية:** ⭐⭐⭐ عالي التأثير

### D3. التقرير الصوتي المباشر (Voice-to-Report)
- **الفكرة:** الطبيب يتكلم ← النظام يكتب التقرير الطبي تلقائياً
- **آلية العمل:**
  - دمج Whisper (Local Medical Fine-Tuned) في عارض الصور
  - تحويل الصوت لنص طبي دقيق
  - ملء بيانات التقرير من ميتاداتا DICOM تلقائياً
- **التقنية:** `openai-whisper` (local) + FastAPI
- **الأولوية:** ⭐⭐ قيمة عالية

### D4. بصمة الحماية والتتبع (Tamper-Evident Audit Trail)
- **الفكرة:** ضمان عدم التلاعب بالصور الطبية لأغراض قانونية
- **آلية العمل:**
  - عند استقبال صورة: حساب SHA-256 hash وتسجيله
  - عند عرض/تصدير صورة: إعادة حساب hash ومقارنته
  - تسجيل كل عملية في Immutable Audit Log
- **التقنية:** `hashlib.sha256()` + MySQL audit_log
- **الأولوية:** ⭐⭐ مهم للجانب القانوني
